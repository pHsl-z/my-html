# my-html

单文件 HTML 编辑器：左边写代码，右边实时预览，支持导出 HTML / Word(DOCX) / PDF / 图片，可打印，可云同步收藏夹。

- 线上地址：https://phsl-z.github.io/my-html/
- 本地入口：`index.html`（整个程序就是一个文件，双击即可离线使用）
- GitHub Pages 有 CDN 缓存，推送后最长约 10 分钟才看到新版本
- 当前版本：**v1.38**（2026-11-04）

## 版本号维护约定

每次发布新版本时，同步更新 `index.html` 顶部的两个常量（在 `showHelp()` 之前）：

```js
const APP_VERSION = 'v1.38';          // 版本号，每次发布递增
const APP_BUILD_TIME = '2026-11-04 02:28';  // 兜底更新时间（离线打开时显示）
```

欢迎界面底部会显示「版本 v1.38 · 更新 2026-11-04 02:28（AI 修改）」。其中时间优先读取页面自身的 `Last-Modified`（即本次部署的真实时间），取不到时才用 `APP_BUILD_TIME`。

## 近期更新记录

### v1.38 · 2026-11-04

**0. iOS 横屏：标题栏收进右侧竖栏，预览铺满全高**
- 现象：iPhone 横屏时代码窗口折叠，「AI文档」和「预览」两行标题栏各占 63px，共吃掉 126px（390px 高的 1/3），预览只剩 261px 高
- 改法：横屏 + 代码窗口折叠时，把两块标题栏搬进右侧 124px 竖栏（AI文档 + 复制/打开/清空/粘贴，预览 + 编辑/全屏/打印/导出图片），预览独占左侧 718×388
- 竖栏固定右侧，下拉菜单靠右向左展开；竖屏、展开代码窗口、全屏预览时自动还原原布局
- 预览区变窄后比 A4 页（794px）窄，会自动把预览缩放到刚好放下整页（本机实测 90%，右下角 pill 可点一下重置），避免每行末尾被右边缘截断
- 侧栏模式下提示消息改挂 body，用视口定位，不会因为代码面板隐藏而看不见

### v1.37 · 2026-11-04

**0. 打印：修复 iOS 打印面板里连续缩放后预览变空白页**
- 现象：进入 iOS 打印页后连续调节缩放（如调到 95%），前几秒正常，过一会儿再点缩放，打印预览变成空白页
- 原因：打印面板打开期间 WebKit 会随面板重渲染反复"假触发"窗口 `focus`；旧代码在 `blur → focus` 后自动 `location.reload()`，面板重渲染时抓到正在加载的空白文档
- 修复：彻底移除 `blur`/`focus` 自动返回逻辑，面板打开期间绝不再整页替换；返回编辑器统一由顶部控制条「↩ 返回编辑器」按钮触发
- 代价：打印结束后需要手动点一下「↩ 返回编辑器」，换来预览不再变白

### v1.36 · 2026-11-03

**0. 打印：`.page` 结构也纳入宽度收窄（修复 iOS 右侧裁切根因）**
- 之前 `.page` 文档走的是"@page 边距 0"分支，块宽仍为 210mm；iOS 打印会套用自己的页边距（约 12mm），于是右侧被裁约 24mm
- 现在 `.page` 与 `.a4-page` 等纸张块统一处理：边距 12mm，块宽收到 168mm，文字重新折行，高度按内容判断
- 实测 6 篇范文（`.page` 结构，8pt）：块 168×168/159mm，横向溢出 0px，快照 PDF 2 页，第一页三篇完整

### v1.35 · 2026-11-03

**1. 欢迎界面显示版本号与更新时间**
- 欢迎弹窗最底部（「关闭」按钮下方）显示「版本 v1.36 · 更新 2026-11-03 22:38（AI 修改）」
- 版本号来自常量 `APP_VERSION`，每次发布递增；时间自动读取页面自身的 `Last-Modified`（即本次部署时间），不需要手动维护
- 离线打开（file://）时取不到服务器时间，回退到内置常量 `APP_BUILD_TIME`

**2. 打印：A4 纸张块自动收进可打印区域（桌面 + iOS）**
- 问题：文档里用 `.a4-page { width: 210mm }` 自己排 A4 时，打印还有 12mm 页边距，可打印宽只有 186mm，右侧文字被裁掉
- 修复：打印前识别纸张块（`.page` / `.a4-page` / `.paper` / `.sheet` / `.page-a4`，没写类名时按 body 子元素 ≥190×240mm 识别），把**真实布局宽度**收到可打印宽度（留 18mm 安全余量），文字重新折行
- 同时解除 `min-height: 297mm`，按内容实际高度判断；确实超出可打印高度时才用 `transform` 等比压缩
- 为什么不缩放：iOS 打印引擎会忽略 `zoom`，靠缩放仍会横向裁切；收窄布局宽度与引擎无关，任何情况下都不会超出纸张
- 双保险：除内联 `width !important` 外，快照里还有一条 `.__pfit` 类规则再约束一次宽度，并把图片/表格/代码块等子元素限宽为 100%，避免个别元素撑破版面
- 打印完自动还原预览，预览界面不受影响

**3. 导出图片：9 种方案 + 默认方案**
- 预览菜单新增「🖼️ 图片多方案导出」，面板与 PDF 多方案一致：每张卡片有「🚀 导出图片」「▶ 测试」、倍率 1x/2x/3x、全部测试
- 9 种方案：html2canvas 1.4.1、html-to-image、modern-screenshot、snapdom、dom-to-image、手工 foreignObject、html2canvas-pro、dom-to-image-more、html2canvas 增强版
- **iPhone 实测结论：只有方案 7（html2canvas-pro）能成功出图**，卡片已加绿色「✅ iPhone 实测可用」标记
- 主界面「导出图片」按钮已统一改用方案 7（桌面同样生效），库下载失败时自动回退原版 html2canvas

**4. 导出图片公式重影修复**
- 原因：MathJax 每个公式内部带隐藏的 `<mjx-assistive-mml>`（给屏幕阅读器用），html2canvas 会把它画出来，叠加在公式上形成重影
- 修复：导出前移除这些隐藏节点（主「导出图片」和 9 个方案全部生效）
- 实测效果：131 处重影消除，导出耗时 19.9s → 7.5s

**5. iOS 预览滚动优化（普通态 + 全屏态）**
- 预览 iframe 强制独立 GPU 合成层，减少滚动重绘阻塞
- 预览文档的触摸兼容垫片监听器改为 passive，不再拖慢滚动启动
- 超大文档（几万个节点）掉帧主要受设备性能限制，优化改善跟手度但无法完全消除

## 打印行为说明

| 文档结构 | 处理方式 |
|---|---|
| 有 `.page` 分页结构 | 与纸张块一致：边距 12mm，块宽收到 168mm，按内容高度判断 |
| 有自定义纸张块（`.a4-page` 等） | 块宽收到可打印宽度（约 168mm），内容折行；需要时再压缩高度 |
| 普通流式文档 | `@page` 边距 12mm，内容自然分页 |

打印时底部会提示本次的处理方式（iOS 顶部的控制条也会显示），例如「已自动收进 A4 可打印区域（2 页）」「已自动缩放 第 1 页（89%）」。
